# Part 1. 유저 시나리오 기반 기능 정의

## 1.1 시나리오 개요

본 서비스는 사용자가 **브랜드/상품을 탐색**하고,
관심 브랜드/상품에 **좋아요(Like)** 를 표시하며,
상품을 **장바구니에 담아 주문을 생성/조회**할 수 있는 **이커머스 플랫폼**이다.

- **P0(첫 번째 설계/구현)**: 브랜드/상품 조회, 좋아요, 장바구니, 주문 생성/조회, 관리자(브랜드/상품 운영 및 주문 조회, 삭제/삭제정책)
- **P1(2단계 확장)**: **인증된 사용자(USER/ADMIN)의 주요 행동 이벤트 기록**(비동기/멱등, 실패 분리)
    - 단, **비회원(GUEST) 행동 이벤트는 기록하지 않는다.**
- **P2(향후 확장)**: 카테고리/배송지/상품옵션(옵션 단위 재고·가격 및 주문 항목 옵션화), 결제/쿠폰/프로모션, 주문 상태 확장(취소/교환/반품), 추천/랭킹/리뷰, 마케팅/리워드/통계 고도화

## 1.2 문제 상황 재해석 (Problem Context)

### 사용자 관점
- 카탈로그 탐색: 다수 브랜드/상품에서 원하는 것을 빠르게 못 찾으면 이탈
- 관심 표현: 탐색 중 발견한 상품을 나중에 다시 찾으려면 기억에 의존
- 구매 안전성: 중복 클릭/네트워크 재시도로 이중 주문·이중 차감 위험

### 비즈니스 관점
- 카탈로그 무결성: 브랜드-상품 참조 관계가 깨지면 운영 데이터 일관성 훼손
- 주문 이력 보존: 상품 삭제/수정 후에도 과거 주문을 정확히 조회해야 함 (CS, 정산)
- 재고 정합성: 동시 주문 시 실물 재고와 시스템 재고 불일치 방지

### 시스템 관점
- 읽기/쓰기 부하 분리: 카탈로그 조회는 고트래픽, 주문/재고는 원자성 중요
- 크로스 도메인 정합성: 주문 시 Cart·Product·Order가 하나의 트랜잭션에 관여
- 삭제 후 참조: Soft Delete 시 좋아요·장바구니가 삭제된 리소스를 참조하는 처리

## 1.3 공통 규칙 및 확정 정책

### 공통 규칙 (P0)

- 조회(Query)는 비회원에게 허용될 수 있다.
- 상태 변경(Command)은 인증된 사용자에게만 허용된다.
- 회원 사용자는 본인이 생성한 리소스(좋아요, 장바구니, 주문 등)만 조회하거나 변경할 수 있다.
- 관리자는 모든 리소스에 대해 조회/변경 권한을 가진다. (단, P0 범위 내 기능에 한함)
- **인증/계정(회원가입/로그인/토큰/비밀번호 등)은 본 설계에서 제외한다.** (이미 구현됨)

### 확정 정책 (P0)

#### 상태코드 규칙 (단일 코드 고정)

| 상황 | 코드 | 비고 |
|------|------|------|
| 인증 실패 (비회원의 Command 시도) | 401 | |
| 권한 부족 / 소유권 위반 | 404 | 리소스 존재 여부를 마스킹 (404 Not Found로 통일) |
| 리소스 없음 / 삭제됨 | 404 | |
| 입력 검증 실패 | 400 | |
| 상태 충돌 / 동시성 / 정책 위반 | 409 | 브랜드 삭제 정책 위반, 재고 부족, 락 타임아웃 포함 |
| 서버 장애 / 타임아웃 | 503 | DB/캐시 장애 등 인프라 수준 |

#### 멱등성 규칙

| 대상 | 동작 |
|------|------|
| 좋아요 등록 (중복) | 상태 변화 없이 성공 반환 |
| 좋아요 취소 (미등록 대상) | 404 반환 |
| 삭제 요청 (이미 삭제됨) | 404 반환 |
| 주문 생성 (동일 요청 재전송) | 최초 생성된 주문 결과 재반환 (재고 중복 차감 없음) |

#### 주문 정책

- 주문 성공 후 장바구니: **주문에 포함된 선택 항목을 즉시 제거**한다.
- 품절 시 주문: **All-or-Nothing** — 하나라도 재고 부족이면 전체 주문 실패 (409), 부분 차감 없음.
- 주문 시점 가격: 주문 시점 가격으로 스냅샷 저장. 장바구니 시점과 차이가 나도 별도 고지 없이 생성.

#### 장바구니 정책

- 동일 상품 재추가: **기존 라인의 수량에 합산**한다 (새 라인 생성 아님).
- 삭제된 상품의 장바구니 항목: **ProductDeletedEvent를 통해 해당 상품의 CartItem을 즉시 제거(Hard Delete)한다.**

#### 좋아요 정책

- 삭제된 리소스의 좋아요: 좋아요 목록 조회 시 **삭제된 리소스는 필터링하여 노출하지 않는다**.

## 1.4 액터별 기능 정의

- 본 서비스에서 이루어지는 행동의 주체(Actor)를 정의한다.
- 액터 정의는 각 주체가 시스템에서 가지는 책임과 권한의 범위를 명확히 하는 데 목적이 있다.
- 기능은 중요도에 따라 다음과 같이 반영한다.
    - P0: 액터 정의에 직접 포함 (첫 번째 설계/구현 범위)
    - P1: 첫 번째 설계/구현 이후 확장 (두 번째 단계)
    - P2: 향후 확장 항목

### 비회원 사용자 (GUEST)

#### 조회 (P0)

- 브랜드 목록을 조회할 수 있다.
- 단일 브랜드의 상세 정보를 조회할 수 있다.
- 전체 상품 목록을 조회할 수 있다.
- 특정 브랜드에 속한 상품 목록을 조회할 수 있다.
- 상품 상세 정보를 조회할 수 있다.

#### 제한 (P0)

- 좋아요, 장바구니, 주문 등 상태를 변경하는 행동은 수행할 수 없다.
- 상태 변경 시도를 할 경우 로그인 또는 회원가입이 필요하다.

---

### 회원 사용자 (USER)

#### 조회 (P0)

- 브랜드 목록 및 브랜드 상세 정보를 조회할 수 있다.
- 전체 상품 목록 및 상품 상세 정보를 조회할 수 있다.
- 특정 브랜드에 속한 상품 목록을 조회할 수 있다.
- 본인이 좋아요한 브랜드/상품 목록을 조회할 수 있다.
- 본인의 장바구니를 조회할 수 있다.
- 본인이 생성한 주문 목록/상세를 조회할 수 있다.

#### 좋아요 / 선호 (P0)

- 브랜드 또는 상품에 대한 선호(Like)를 표현할 수 있다.
- 이미 표현한 선호를 취소할 수 있다.

#### 장바구니 (P0)

- **상품(Product) 단위**로 상품을 장바구니에 담을 수 있다.
- 장바구니에 담긴 상품의 수량을 변경할 수 있다.
- 장바구니에 담긴 상품을 삭제할 수 있다.
- 장바구니에 담긴 일부 또는 전체 상품을 주문 대상으로 선택할 수 있다.
- 장바구니 내 상품의 상태(품절 여부 등)를 확인할 수 있다.

#### 주문 (P0)

- 단일 또는 복수 상품을 주문할 수 있다.
- 주문 시점의 상품 정보(가격, 상품명 등)는 스냅샷으로 보존된다.
- 주문 요청 시 상품 단위로 재고 확인 및 차감이 보장되어야 한다.

---

### 관리자 (ADMIN)

> 관리자는 LDAP 인증을 통해 식별된다. (인증 자체는 범위 외)

#### 브랜드 관리 (P0)

- 브랜드를 등록할 수 있다.
- 브랜드 목록을 조회할 수 있다.
- 단일 브랜드의 상세 정보를 조회할 수 있다.
- 브랜드 정보를 수정할 수 있다.
- 브랜드를 삭제할 수 있다.

##### 브랜드 삭제 정책 (P0)

- **브랜드를 삭제하려면, 해당 브랜드에 속한 "활성(미삭제)" 상품이 0개여야 한다.**
- **브랜드에 속한 상품이 1개라도 남아 있으면 브랜드 삭제는 실패한다.**
- (권장) Soft Delete를 사용할 경우에도 "활성 상품 0개" 조건을 동일하게 적용한다.

#### 상품 관리 (P0)

- 상품을 등록할 수 있다. (브랜드 지정)
- 상품의 가격 및 재고를 관리(설정/수정)할 수 있다.
- 등록된 상품 목록을 조회할 수 있다.
- 단일 상품의 상세 정보를 조회할 수 있다.
- 상품 정보를 수정할 수 있다.
- 상품을 삭제할 수 있다.

##### 상품 삭제 정책 (P0)

- **P0에서는 주문 생성 직후 해당 주문을 "거래 종료"로 간주한다.**
    - 따라서 **주문 이력이 존재하더라도 상품 삭제는 허용된다.**
- (설명) 주문 상태 확장(P2) 도입 후에는,
    - `주문생성 → 배송중 → 배송완료 → 주문확정` 등의 상태 전이를 추가하고,
    - "모든 관련 주문이 주문확정(거래종료)일 때만 삭제 가능"처럼 삭제 조건을 강화한다.

#### 주문 조회 (P0)

- 전체 주문 목록을 조회할 수 있다.
- 단일 주문의 상세를 조회할 수 있다.

---

### 시스템 (SYSTEM)

#### 이벤트 및 비동기 처리 (P1)

- **인증된 사용자(USER/ADMIN)의 주요 탐색 및 행동(브랜드 조회, 상품 조회, 좋아요, 장바구니 변경, 주문 등)을 이벤트로 기록한다.**
- 이벤트 처리는 중복 수신 시에도 멱등하게 처리되어야 한다.
- 핵심 트랜잭션(주문, 재고 차감 등)은 이벤트 처리 실패와 분리되어야 한다.
- 비동기 처리 실패는 사용자 요청의 성공/실패에 영향을 주지 않는다.
- 비회원(GUEST)의 행동 이벤트는 기록하지 않는다.

## 1.5 향후 확장 (P2)

- 상품 옵션(Product Option) 단위(옵션 선택/재고/가격) 및 "주문 항목 옵션 단위" 정책
- 결제/쿠폰/프로모션
- 주문 상태 확장(취소/교환/반품 등) 및 관리자 처리(승인/거절)
- 추천/랭킹/리뷰

# Part 2. 핵심 유저 시나리오 — Happy Path (Slim P0)

- 본 문서는 **정상 흐름(성공 케이스)** 중심의 핵심 시나리오만 다룬다.
- 인증/계정(회원가입/로그인/토큰/비밀번호 등)은 **설계 범위에서 제외**한다. (이미 구현됨)
- 비회원(GUEST)은 조회만 가능하다.
- 본 문서는 최대한 작은 P0로 진행하며, 확장 항목은 P1/P2로 미룬다.

## 2.0 P1/P2(향후 확장)로 미루는 항목

### P1

- 시스템 이벤트 기록 및 비동기 처리(멱등/실패 분리 등)
    - 단, 비회원(GUEST) 행동 이벤트는 기록하지 않는다.

### P2

- 카테고리 기반 탐색/관리
- 배송지 및 주문 배송지 포함, 배송비 계산
- 상품 옵션 단위(옵션 선택/재고/가격) 및 "주문 항목 옵션 단위"
- 결제/쿠폰/프로모션
- 주문 상태 확장(취소/교환/반품 등)
- 추천/랭킹/리뷰

---

## 2.1 공통 용어 (Slim)

- **브랜드(Brand)**: 상품을 소유/분류하는 단위
- **상품(Product)**: 판매 단위 (P0에서는 옵션 없이 단일 가격/재고를 가진다고 가정)
- **장바구니(Cart)**: 회원 단위로 관리되는 주문 이전 상태(상품 + 수량)
- **주문(Order)**: 하나 이상의 상품으로 구성되며, 주문 시점 스냅샷(가격/상품명 등)을 보존

---

## 2.2 비회원(GUEST) 핵심 시나리오: 카탈로그 탐색 (조회 전용)

### 2.2.1 브랜드 기반 탐색

- 사용자는 브랜드 목록을 조회한다.
- 사용자는 브랜드 상세 정보를 조회한다.
- 사용자는 해당 브랜드의 상품 목록을 조회한다.
- 사용자는 상품 상세를 조회한다.

### 2.2.2 전체 상품 탐색

- 사용자는 전체 상품 목록을 조회한다.
- 사용자는 정렬/필터(브랜드 등)를 적용해 탐색한다.
- 사용자는 상품 상세를 조회한다.

---

## 2.3 회원(USER) 핵심 시나리오: 탐색 → 좋아요 → 장바구니 → 주문 → 주문조회

### 2.3.1 상품 탐색 및 좋아요

- 사용자는 브랜드/전체 상품 목록을 탐색한다.
- 사용자는 상품 상세를 확인한다.
- 사용자는 관심 브랜드 또는 상품에 좋아요(Like)를 등록한다.
- 사용자는 좋아요 목록을 조회한다.
- 사용자는 좋아요를 취소할 수 있다.

### 2.3.2 장바구니 구성

- 사용자는 상품을 장바구니에 담는다.
- 사용자는 장바구니를 조회한다.
- 사용자는 장바구니 항목 수량을 변경한다.
- 사용자는 장바구니 항목을 삭제할 수 있다.
- 사용자는 주문 대상으로 일부/전체 장바구니 항목을 선택한다.
- 사용자는 선택 항목의 상태(품절 여부 등)를 확인한다.

### 2.3.3 주문 생성 (P0)

- 사용자는 선택한 장바구니 항목(상품 단위)으로 주문을 요청한다.
- 시스템은 주문 요청 시점에:
    - 주문 항목을 상품 단위로 구성한다.
    - 상품별 재고를 확인하고, 재고 차감을 보장한다.
    - 주문 시점의 상품 정보(가격, 상품명 등)를 스냅샷으로 저장한다.
- 시스템은 주문 생성 결과(주문 번호/주문 상세)를 반환한다.
- 주문에 포함된 선택 항목은 장바구니에서 즉시 제거한다.

### 2.3.4 주문 조회

- 사용자는 본인의 주문 목록을 조회한다.
- 사용자는 특정 주문 상세를 조회한다.
- 사용자는 주문 상세에서 주문 항목(상품 단위), 스냅샷 정보를 확인한다.

---

## 2.4 관리자(ADMIN) 핵심 시나리오: 카탈로그 운영 → 주문 조회 → 삭제(정책 준수)

### 2.4.1 브랜드 등록 및 조회/수정

- 관리자는 브랜드를 등록한다.
- 관리자는 브랜드 목록/상세를 조회한다.
- 관리자는 브랜드 정보를 수정한다.

### 2.4.2 상품 등록 및 가격/재고 설정/수정

- 관리자는 상품을 등록한다. (브랜드 지정)
- 관리자는 상품의 가격 및 재고를 설정한다.
- 관리자는 상품 목록/상세를 조회한다.
- 관리자는 상품 정보(상품명/가격/재고)를 수정한다.

### 2.4.3 주문 조회

- 관리자는 전체 주문 목록을 조회한다.
- 관리자는 특정 주문 상세를 조회한다.

### 2.4.4 상품 삭제 (P0, 성공 케이스)

- 관리자는 상품 상세를 조회한다.
- 관리자는 상품 삭제를 요청한다.
- 시스템은 상품을 삭제 처리한다.
- 관리자는 상품 목록/상세 조회로 삭제 결과를 확인한다.

> 참고: P0에서는 주문 생성 직후 거래 종료로 간주하므로, 주문 이력이 존재하더라도 상품 삭제는 허용된다.
> 주문 상세는 스냅샷 기반으로 조회 가능해야 한다.

### 2.4.5 브랜드 삭제 (P0, 성공 케이스: 브랜드 내 상품 0개)

- 관리자는 브랜드에 속한 상품 목록을 조회한다.
- 관리자는 해당 브랜드에 속한 모든 상품을 먼저 삭제한다. (2.4.4)
- 시스템은 브랜드에 속한 "활성(미삭제)" 상품이 0개임을 확인한다.
- 관리자는 브랜드 삭제를 요청한다.
- 시스템은 브랜드를 삭제 처리한다.
- 관리자는 브랜드 목록/상세 조회로 삭제 결과를 확인한다.

# Part 3. 핵심 유저 시나리오 — Alternative/Exception Path (Slim P0)

- 본 문서는 **Happy Path(성공 케이스)** 를 제외한 **대안 흐름(성공 변형)** 과 **예외 흐름(실패/차단/오류)** 만 다룬다.
- 인증/계정은 범위에서 제외한다(이미 구현됨).
- **시스템 이벤트 기록/비동기 처리**는 P1로 미루며, 본 문서(P0)에서는 다루지 않는다.
- 카테고리/배송지/상품옵션/결제/쿠폰/주문상태확장/추천·랭킹·리뷰는 P2로 미루며 본 문서에서 다루지 않는다.
- 단, **관리자 삭제 및 삭제 정책은 P0에 포함**되므로 본 문서에서 다룬다.

## 3.0 공통 규칙 기반 Alternative/Exception

### 3.0.1 공통 Alternative Path (성공 변형)

#### AP-0-1-01. 목록 조회의 정렬/필터/페이지네이션 변형 (성공)

- 트리거: 목록 조회 시 sort/filter/page 파라미터 포함
- 결과: 유효한 조합이면 정상 반환

#### AP-0-1-02. 멱등 요청으로 인한 "이미 처리됨" 성공 응답 (성공)

- 트리거: 동일 요청 재전송(네트워크 재시도/중복 클릭)
- 결과: 중복 감지 후 동일 결과 반환(부작용 없음)

### 3.0.2 공통 Exception Path (실패/차단)

#### EP-0-2-01. 권한 없음 (GUEST의 Command 시도)

- 트리거: 비회원이 좋아요/장바구니/주문 등 상태 변경 요청
- 결과: 401 + 로그인 필요

#### EP-0-2-02. 리소스 소유권 위반 (USER가 타인의 리소스 접근)

- 트리거: USER가 타인의 주문/장바구니 항목 접근 시도
- 결과: 404 (리소스 존재 노출 방지)

#### EP-0-2-03. 리소스 없음 / 삭제됨

- 트리거: brand/product/order/cartItem 등이 존재하지 않거나 삭제됨
- 결과: 404

#### EP-0-2-04. 유효성 검증 실패

- 트리거: 잘못된 입력(수량 0/음수 등)
- 결과: 400

#### EP-0-2-05. 동시성 충돌 / 상태 불일치

- 트리거: 동시에 업데이트(장바구니 수량 동시 변경, 주문 중복 생성 경쟁 등)
- 결과: 409

#### EP-0-2-06. 시스템 장애/타임아웃

- 트리거: DB/캐시 장애, 타임아웃
- 결과: 503
- 주의: (주문/재고) 핵심 트랜잭션은 원자성 유지(부분 커밋 금지)

### EP-1-1-01. 브랜드 없음/삭제됨

- 결과: 404

### EP-1-1-02. 상품 상세 조회 시 상품이 삭제됨(탐색 중 변경)

- 결과: 404

### EP-1-1-03. 잘못된 정렬/필터 값

- 결과: 400

## 3.2 회원(USER) Alternative/Exception: 좋아요 → 장바구니 → 주문 → 주문조회

### 3.2.1 좋아요

#### AP-2-1-01. 좋아요 중복 요청(멱등 성공)

- 트리거: 이미 좋아요한 대상에 다시 좋아요 요청
- 결과: 상태 변화 없이 성공

#### AP-2-1-02. 좋아요 취소 (미등록 대상)

- 트리거: 좋아요하지 않은 대상에 취소 요청
- 결과: 404

#### EP-2-1-01. 좋아요 대상 리소스 없음/삭제됨

- 결과: 404

---

### 3.2.2 장바구니

#### AP-2-2-01. 동일 상품 추가 시 라인 병합 (성공)

- 트리거: 동일 상품을 장바구니에 재추가
- 결과: 기존 라인의 수량에 합산

#### EP-2-2-01. 장바구니 수량 변경: 0 이하 요청

- 결과: 400 (삭제 기능 사용 유도)

#### EP-2-2-02. 장바구니/주문 단계에서 품절 감지

- 트리거: 장바구니에 담긴 상품이 품절 상태로 변경됨
- 결과: 주문 생성 실패(409). 부분 주문 없음(All-or-Nothing)

#### EP-2-2-03. 타인 장바구니 항목 접근

- 결과: 404 (리소스 존재 노출 방지)

---

### 3.2.3 주문 생성 (P0)

#### AP-2-3-01. 주문 생성 요청 재전송(멱등 성공)

- 트리거: 네트워크 재시도 등으로 동일 요청 재전송
- 결과: 기존 생성된 주문 반환(재고 중복 차감 방지)

#### AP-2-3-02. 주문 시점 스냅샷 기준 가격 반영 (성공)

- 트리거: 장바구니 시점과 주문 시점 가격이 다름
- 결과: 주문은 주문 시점 가격으로 스냅샷 저장 후 생성

#### EP-2-3-01. 주문 대상 장바구니 항목 없음

- 트리거: 선택 항목 비어있음 / 이미 삭제됨
- 결과: 400

#### EP-2-3-02. 재고 부족(동시 주문 경쟁 포함)

- 트리거: 하나 이상의 상품이 재고 부족
- 결과: 409 + 주문 생성 실패 + 재고 부분 차감 없음(원자성)

#### EP-2-3-03. 재고 차감 중 락 타임아웃/충돌

- 결과: 409, 주문 생성 없음(롤백)

---

### 3.2.4 주문 조회

#### AP-2-4-01. 주문 상세는 스냅샷 기반으로 조회 가능 (성공 변형)

- 트리거: 주문에 포함된 상품이 현재는 삭제됨
- 결과:
    - 주문 상세는 스냅샷(상품명/가격 등) 기반으로 정상 조회
    - "현재 상품 페이지 이동" 링크는 비활성화된다

#### EP-2-4-01. 타인 주문 조회 시도

- 결과: 404 (리소스 존재 노출 방지)

#### EP-2-4-02. 주문 없음/삭제됨

- 결과: 404(상세) 또는 빈 목록(목록)

---

## 3.3 관리자(ADMIN) Alternative/Exception: 브랜드/상품 운영 및 주문 조회 + 삭제(정책 포함)

### 3.3.1 등록/수정/조회 예외

#### EP-3-1-01. 등록/수정 유효성 실패(필수값 누락/형식 오류)

- 결과: 400

#### EP-3-1-02. 참조 오류(존재하지 않는 브랜드에 상품 등록 시도)

- 결과: 404

#### EP-3-1-03. 동시 수정 충돌(낙관적 락)

- 결과: 409

#### EP-3-1-04. 주문 상세 조회 대상 없음/삭제됨

- 결과: 404

### 3.3.2 삭제/삭제정책 예외 (P0)

#### AP-3-2-01. 삭제 요청 재전송

- 트리거: 동일 삭제 요청이 재전송됨(중복 클릭/재시도)
- 결과: 404

#### EP-3-2-01. 브랜드 삭제 정책 위반(브랜드 내 상품 잔존)

- 트리거: 브랜드 삭제 요청 시, 해당 브랜드에 속한 "활성(미삭제)" 상품이 1개 이상 존재
- 결과: 409 + 실패 사유(상품 잔존) 반환

#### EP-3-2-02. 브랜드 삭제 중 경쟁 상태(동시 상품 생성/복구 등)

- 트리거: 브랜드 삭제 직전/중간에 다른 작업으로 상품이 생성/활성화됨
- 결과: 409 + 재시도 유도

#### EP-3-2-03. 상품 삭제 대상 없음/이미 삭제됨

- 결과: 404

#### EP-3-2-04. 삭제 처리 중 시스템 장애

- 트리거: 삭제 트랜잭션 중 DB 오류/타임아웃 등
- 결과: 503

# Part 4. 요구사항 명세 (Slim P0)

## 4.0 공통 규칙

- USER 인증 필요: `user_required = O`
- ADMIN(LDAP) 인증 필요: `ldap_required = O`
- 목록 조회 API는 기본적으로 페이지네이션(`page`,`size`)을 지원한다.

### 에러 응답 공통 스키마

모든 4xx/5xx 응답은 아래 형식을 따른다:

| 필드 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `code` | String | 에러 식별 코드 (UPPER_SNAKE_CASE) | `ORDER_OUT_OF_STOCK` |
| `message` | String | 사람이 읽을 수 있는 메시지 | `재고가 부족합니다` |
| `traceId` | String | 문제 추적용 ID | `abc-123-def` |
| `timestamp` | String | 발생 시각 (ISO-8601 UTC) | `2026-02-13T10:30:00Z` |

---

## 4.1 Brand Domain (Brand)

### 📌 4.1.1 User 목표, 요구사항 명세

- **GUEST/USER**: 브랜드를 탐색(목록/상세)하고, 브랜드 기준으로 상품을 찾기 위한 진입점을 얻고 싶다.

| **METHOD** | **URI**                    | **user_required** | **특징**                | **설명**    |
|------------|----------------------------|-------------------|-----------------------|-----------|
| GET        | `/api/v1/brands`           | X                 | 페이지네이션(`page`,`size`) | 브랜드 목록 조회 |
| GET        | `/api/v1/brands/{brandId}` | X                 |                       | 브랜드 정보 조회 |

#### ✅ 브랜드 목록 조회 쿼리 파라미터

| **파라미터** | **예시** | **설명**              |
|----------|--------|---------------------|
| `page`   | `0`    | 페이지 번호 (기본값 0)      |
| `size`   | `20`   | 페이지당 브랜드 수 (기본값 20) |

---

### 📌 4.1.2 Admin 목표, 요구사항 명세

- **ADMIN**: 브랜드를 등록/수정/삭제하여 카탈로그를 운영하고 싶다.

| **METHOD** | **URI**                          | **ldap_required** | **특징**                | **설명**                              |
|------------|----------------------------------|-------------------|-----------------------|-------------------------------------|
| GET        | `/api-admin/v1/brands`           | O                 | 페이지네이션(`page`,`size`) | 등록된 브랜드 목록 조회                       |
